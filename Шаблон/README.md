Единицы: координаты ЛИРА в **метрах**; Ø/шаг/длины зон в **мм**; As/фон в **см²/м**.
В Revit длины м/мм → футы (`× 3.280839895`) **только** в `ZonePlacer`. Core не хранит футы.

Активный поток строит зоны из пятен и их ограничивающих рамок. Прежний `ZoneLayoutEngine` перенесён в `Legacy/ZoneLayoutEngine.cs`; его многопроходная постобработка не используется для текущей раскладки.

1. `BuildResult` выбирает КЭ указанной отметки, затем получает контур плиты и обнаруженные отверстия.
2. `MosaicBuilder` строит регулярную мозаику отдельно для каждого включённого слоя. Из As КЭ вычитается фоновое армирование слоя; остаток выше численного допуска записывается во все ячейки с ненулевой площадью пересечения реального контура КЭ. В ячейке сохраняются ID пересекающих её КЭ; вклад значения объединяется максимумом, а не суммой. Размер ячейки задаётся `GridCellMm`.
3. `ZonePatchAnalyzer` сортирует положительные ячейки по убыванию остатка и растит пятно обходом четырёх соседей. Ступени детализации сохраняют пороги текущего алгоритма; направление разбиения следует оси слоя: X — по горизонтали, Y — по вертикали. Поперёк оси активные ячейки объединяются в ширину пятна.
4. Минимальное число КЭ считается по уникальным ID во всём пятне, а не по числу ячеек. Закрашиваются реальные контуры КЭ, попавших в пятно. Рамка вычисляется по крайним координатам этих контуров и полностью охватывает окрашенные КЭ; это ограничивающий прямоугольник, а не точный контур их объединения.

Зоны строит `ZonePatchZoneBuilder` внутри рамки активных пятен. Галочка «Осреднять пики» по умолчанию выключена: без неё параметры выбираются по максимальному исходному превышению As; при включении спрос для подбора усредняется по соседним ячейкам мозаики. Диаметр не ниже фонового, варианты шага — 200 и 100 мм; выбирается достаточный вариант с приоритетом меньшей расчётной добавки стали. Для текущей автоматической генерации используется семейство прямых стержней. Из правил Legacy задействованы только явно разрешённые таблицы бетона, анкеровки, нахлёста и типовых длин; прямые детали ограничены 11700 мм и при необходимости делятся с нахлёстом `2 × LapLen`.

После построения разрешено узкое объединение. Сначала одинаковые прямые зоны можно сдвинуть вдоль стержней и объединить, если сохраняются анкеровка, достаточность арматуры и длина детали. Затем соприкасающиеся зоны объединяются поперёк стержней только при совпадении слоя, направления, диаметра, шага, семейства и длины; геометрическое объединение принимается, только если длина остаётся прежней (погрешность до 1 мм). Поэтому, например, смежные зоны `Ø22`, `2900 мм`, шаг `200 мм` могут стать одной более широкой зоной без изменения этих параметров. Общая legacy-постобработка пересечений и зазоров этим не включается.

Предпросмотр закрашивает реальные контуры КЭ, участвующих в пятнах; пустые участки сетки не окрашиваются. Пунктирные рамки охватывают соответствующие закрашенные КЭ. Внутри КЭ выводится требуемая добавка As в см²/м. В текущем regression-тесте отдельно проверяется объединение двух смежных зон при неизменных `Ø22`, `2900 мм` и шаге `200 мм`.

## Справочно: архивная раскладка зон

Описание ниже относится к прежнему пути `Legacy/ZoneLayoutEngine.cs` и сохранено для справки. Оно не является набором дополнительных правил активной раскладки пятен и не включается автоматически.

### Вход, детализация и арматура

1. Для выбранной отметки берутся только горизонтальные пластины. По каждому включённому слою строится мозаика `max(As_КЭ − As_фона, 0)`; ячейки с превышением не более `0,01 см²/м` не запускают зону. Фон вычисляется из заданных Ø и шага. Галочки слоёв определяют участие слоя в расчёте.
2. Все положительные ячейки рассматриваются от большего превышения к меньшему. Связное пятно растёт от кандидата при пороге относительно его пика. Ползунок `Max / 4 / 3 / 2 / Min` задаёт пороги `95 / 85 / 70 / 55 / 1%` соответственно; у `Min` используется абсолютный порог `0,01`. Это влияет на укрупнение, но не гарантирует минимальный расход стали. Промежуточные уровни сглаживают одиночные пики, `Min` использует исходную мозаику.
3. `Мин. число КЭ` считает уникальные окрашенные КЭ связного пятна, а не число ячеек мозаики. Ограничения ширины/длины равны нулю, если фильтр не задан. Из доступных Ø исключаются диаметры, выключенные в меню; выбранный Ø дополнительной арматуры не меньше фонового. Галочка «Разрешить шаги 100 и 200 мм» добавляет шаг 100 к шагу 200, а не заменяет им шаг 200. Подбор Ø/шага должен обеспечить расчётное превышение As.
4. Длина исходного пятна увеличивается на анкеровку с обоих концов по `RebarTables` для класса бетона B15…B40. Ширина округляется до целого числа промежутков между стержнями: `ширина = (число стержней − 1) × шаг`. Для прямого SUM-30 необходимая длина выбирается вверх из типового ряда `1460, 1950, 2340, 2900, 3900, 4680, 5850, 7800, 8800, 11700 мм`. Для гнутых SUM-31…34 полная длина считается как плановая часть плюс одна или две вертикальные полки, без округления по этому ряду.

### Контур, сдвиги и зазоры

1. Исходный прямоугольник сначала подгоняется к габариту плиты, затем `MeshBoundary.ClipRectToSlab` подрезает его по доступной части внешнего контура с заданным отступом. После подрезки длина прямого семейства выбирается из типового ряда **не больше фактически доступной**, ширина повторно приводится к шагу. При слишком малом остатке или невыполнимом минимальном размере кандидат отклоняется.
2. Привязка к осям (`AxisSnapper`) может сдвинуть зону лишь ограниченно. После неё снова выполняются подгонка к плите, подрезка и пересчёт габаритов. Поэтому первоначальная типовая длина и итоговая длина на плане могут различаться.
3. Соседние зоны одного слоя разводятся перпендикулярно стержням. Требуемый зазор пары равен **меньшему шагу** её зон: 100 мм, если хотя бы одна имеет шаг 100; иначе 200 мм. После сдвигов проверяется покрытие пика либо исходного пятна. Неподходящий сдвиг откатывается или кандидат отклоняется; покрытие КЭ имеет приоритет, поэтому конфликт разрешают и финальные проходы нормализации.
4. Постобработка объединяет совместимые зоны, обрезает пустые участки, разбивает недопустимые пересечения, восстанавливает непокрытые положительные КЭ и повторно подгоняет зоны к плите. Это **несколько последовательных проходов**, а не одна операция. Пустая зона может быть удалена. Отметка ячеек как обработанных делается только после успешного создания зоны.
5. Обычное наложение зон одного слоя не допускается. Продольное перекрытие разрешается для стыка, если хотя бы одна зона имеет длину 11700 мм; его длина должна быть **не меньше двух табличных нахлёстов** для большего Ø пары. Это не требование сдвинуть такие зоны на 100/200 мм: правило зазора относится к соседству поперёк стержней. Остальные конфликтующие перекрытия разделяются или отвергаются.

### Отверстия и гнутые детали

- `SlabOpenings.Detect` вычитает объединение контуров КЭ из внешнего контура плиты через Clipper2. Отсутствие КЭ считается отверстием, только если и ширина, и высота пустоты не меньше **двух медианных габаритов КЭ** соответствующего направления. Малые единичные пропуски сетки игнорируются. Дополнительно `HoleBentRules.ShouldIgnoreOpening` игнорирует отверстие с поперечным к стержню размером не больше `HoleIgnorePerpMm` (по умолчанию 200 мм).
- Зона, пересекающая учитываемое отверстие, вычитается и делится на отдельные части. Участки, заканчивающиеся у грани отверстия вдоль стержней, переводятся в гнутые детали при включённых правилах; обходящие отверстие части прямой зоны остаются SUM-30. Выбор гнутого семейства зависит от доступной вертикальной полки `толщина − верхний защитный слой − нижний защитный слой − Ø`: при полке не меньше двух диаметров оправки берётся SUM-32, при полке не меньше одного диаметра оправки SUM-31, иначе SUM-34. Семейства и имена можно изменить вручную.
- При автоматическом разбиении проверяются сохранение привязанных КЭ, минимальная ширина прямой части и конфликты с соседними зонами. Если проверки не проходят, исходная зона остаётся с предупреждением. При ручном редактировании изменённая зона делится по отверстию в `PreviewViewport.CommitEdits`; действие доступно для отмены.

### Предельная длина 11700 мм

- `SplitOverlongZones` делит длинную зону вдоль направления стержней. Для гнутой детали из 11700 мм предварительно вычитается одна или две вертикальные полки. Стыкуемые части перекрываются минимум на `2 × LapLenMm(бетон, Ø)`; следующая часть подбирается по оставшейся длине.
- Каждая часть после подрезки должна сохранить запланированный продольный габарит, покрытие закреплённых КЭ и допустимое соседство. Если разрез выходит за сложный внешний контур, теряет КЭ или конфликтует с соседями, исходная зона остаётся **недействительной**, с причиной в комментарии. `ZonePlacer` блокирует установку при фактической полной длине любого стержня свыше 11700 мм; число таких зон видно в статистике предпросмотра. `PickFamilyLength` сам по себе не является проверкой максимума: он возвращает 11700 и при большем запросе.
- Известный пример на `lira_all_plates.json`, Z=29,450, As2: две длинные зоны у вогнутого внешнего контура пока не удаётся автоматически разделить без потери покрытия КЭ. Их следует исправить вручную и повторно проверить статистику до размещения. Автоматическое устранение **всех** таких случаев пока не реализовано.

### Ручное редактирование в предпросмотре

Режим редактирования использует Clipper2 для создания, перемещения, изменения габаритов (в том числе перетаскиванием грани), разделения, объединения и удаления зон. «Выбрать грань» делит зону **перпендикулярно** выбранной грани. Доступны ручные Ø, шаг 100/200, длина/ширина и семейство. Инструмент зазора: первый щелчок выбирает перемещаемую зону, второй — опорную; сдвиг до меньшего шага двух зон выполняется только если зона после подрезки остаётся допустимой. `Ctrl+Z` хранит до 50 изменений; загрузка другого результата очищает историю. Редактирование геометрии не означает автоматического пересчёта As и не снимает проверку длины при размещении.

## Зафиксированное поведение (что уже сделано)

### 1. Геометрия КЭ
- Пластины = КЭ с 3–4 узлами (стержни исключены).
- Контур упорядочивается в `ContourFix` (сырой TypeAndNodes давал ромбы).
- Габариты зоны — по рёбрам, не AABB.
- Сетка на превью: светлая заливка + тонкие линии.
- Галочка «Контур плиты + серый фон» **удалена**.
- Тёмная обводка Outline и обводка зон **не рисуются** (давали «чёрные линии» поверх КЭ).  
  `Outline` всё ещё считается для статистики/JSON.

### 2. Только горизонтальные плиты + уровни
- В анализ/уровни: пластины, у которых **все узлы на одном Z** (допуск **5 мм**) — `MeshBoundary.IsHorizontalPlate`.
- Стены/наклонные отсекаются.
- UI: «Загрузить уровни из ЛИРЫ» → комбо → «Взять плиту ближайшую к уровню».
- Причина: авто-доминантный этаж брал не ту отметку (напр. +29 вместо +55).
- `AnalysisResult.AllPlates` — все гориз. плиты всех уровней (`[JsonIgnore]` в обычном SaveJson).
- As читается на **все** уровни сразу (смена отметки не теряет As).
- Методы: `RebuildForElevation`, `CollectLevels`, `FilterNearestLevel`.

### 3. As1…As4

| Слой | Обычно |
|------|--------|
| As1 | Нижняя, направление 1 |
| As2 | Нижняя, направление 2 |
| As3 | Верхняя, направление 1 |
| As4 | Верхняя, направление 2 |

Единица: **см²/м**. Зона: `As − фон > ~0.01`.

### 4. Дефолты (актуальные)

| Параметр | Значение |
|----------|----------|
| Фон As1…As4 | Из Ø/шага фоновой арматуры; в DTO без настройки — 0 |
| Мин/макс ширина, мин длина, мин КЭ | **0** (0 = без фильтра / без max) |
| `VisualizationScale` (шаг изополей) | **0** |
| Show As1, As2 | on; As3, As4 | off |
| Сетка КЭ | on |
| Изополя | off |
| Оси из ЛИРЫ | **off** |

Синхронно в: `config/settings.json`, `Models.AnalysisSettings`, XAML.

### 5. Ползунок изополей (`VisualizationScale`)
- Диапазон **0…25** см²/м.
- **0:** цвета зон/изополей = легенда **As1…As4** (изополя — по слою с max As).
- **> 0:** цвет по `floor(As / step)` из **уникальной палитры без повторов** (`DistinctBandBrush`).
- На расчёт зон и Revit **не влияет**.
- Движение ползунка сразу обновляет превью (`SettingsChanged` → `RefreshTransform`).

### 6. Оси
- Таблица `ConstructionAxes`: имя/тип/координата или отрезок; мм→м; дедуп; диагностика в журнале.
- По умолчанию галочка **выкл**.
- Рисунок: кружки **сверху** (верт. оси) и **слева** (гориз.), одна линия; штрих **только снаружи** до края плиты, не сквозь контур.

### 7. Transform (Revit)
- Offset X/Y, Rotation; ↺/↻ ±90°; «Выровнять по осям»; сброс.
- Реально применяется в `PreviewViewport` (`Tx` / `UnTx` / pivot).

### 8. Текст на холсте
- Мир: `Scale(s, -s)` → без компенсации текст вверх ногами.
- Исправлено: `DrawUprightText`.

### 9. JSON
- «Сохранить JSON зон…» → `SaveJson` (зоны текущего уровня).
- «Сохранить JSON всех плит…» → `SaveAllPlatesJson` (все гориз. плиты всех уровней в один файл).
- При загрузке JSON без зон выполняется расчёт выбранного (или доминирующего) уровня; остальные плиты доступны для смены отметки. Обязательные условия раскладки сохраняются.
- Если JSON всех плит не содержит настроек, используются текущие параметры окна. Поле `Levels` читается как список доступных отметок.
- При загрузке JSON поле «Ячейка мозаики» заполняется автоматически наиболее частым меньшим габаритом КЭ выбранного уровня (округление до 10 мм). После загрузки значение можно изменить вручную.
- Контур плиты строится по координатам рёбер: старые JSON с разным порядком `NodeIds` и `Contour` поддерживаются. При новом чтении ЛИРА номера узлов сортируются вместе с координатами.

### 10. Отметка
- Бейдж «Отметка КЭ: …» на холсте + строка в статистике справа.

### 11. Производительность / устойчивость
- `ModelPart: Visible` — текущий видимый фрагмент (не вся модель).
- Батчевое чтение As, soft-fail при ошибках API.
- Векторный `PreviewViewport` (зум без растрового размытия).
- LOD при большом числе КЭ.
- Контур плиты и отверстия кэшируются по точному отпечатку геометрии; повторный расчёт не строит их заново.
- Изменение показа или фонового армирования одного слоя пересчитывает только этот слой As; зоны остальных слоёв сохраняются.
- Финальная коррекция зон выполняется до устойчивого состояния, но не более трёх итераций. Основные проходы раскладки остаются однократными и упорядоченными, чтобы не создавать циклическое смещение зон.
- Для поиска пересечений диагностика использует пространственную сетку вместо полного перебора всех пар зон.
- Отверстия участвуют в обходе и выборе гнутого семейства во время раскладки; фактическое рассечение остаточного пересечения выполняется один раз после стабилизации зон.
- При включённом реверсе As1/As3 раскладываются по Y, As2/As4 — по X. После привязки к осям зона повторно центрируется вдоль этой фактической оси; новое положение принимается только при сохранении покрытия исходных КЭ и анкеровочных выпусков.
- Торец определяется по расстоянию до реального полигонального контура, а не до общего прямоугольного габарита плиты. Поэтому ступенчатые и скруглённые края получают гнутые семейства SUM-31…SUM-34.
- После разбиения стержней 11700 выполняется финальная проверка реверсивной раскладки. Непокрытые КЭ у сложного края восстанавливаются короткими локальными гнутыми зонами; пустые зоны удаляются.

### 12. Диагностика раскладки
- После автоматического или ручного изменения проверяются непокрытые расчётные КЭ, пустые и некорректные зоны, стержни длиннее 11700 мм и недопустимые пересечения.
- Непокрытые КЭ подсвечиваются розовым, ошибки зон — красной рамкой, конфликты — оранжевой.
- Выпадающий фильтр над холстом показывает все ошибки, отдельную категорию или полностью отключает диагностическую подсветку.
- Сводные количества непокрытых КЭ, пустых зон и конфликтов отображаются в правой панели статистики.

### MCP-поиск с короткими ответами

На уровне корня репозитория лежат `.codex/config.toml` и `.cursor/mcp.json`: они подключают локальный `tools/code-search-mcp.cjs` как `lira-code-search`. Нужны Node.js, локальный Ollama с `nomic-embed-text` и Qdrant (`localhost:11434` и `localhost:6333`); внешние npm-пакеты не требуются. После открытия/доверия к проекту перезапустите клиент MCP, чтобы он перечитал конфигурацию. Первая индексация из каталога `Шаблон`: `node tools/vector-index.cjs`; повторный запуск векторизует только изменённые исходники. Проверка протокола и поиска: `node tools/test-code-search-mcp.cjs`.

Для смыслового запроса вызывайте `semantic_search` с малым `limit`, затем `read_lines` для нужного диапазона. MCP строит **настоящие эмбеддинги** C#/XAML/PowerShell через Ollama и ищет их по косинусной близости в Qdrant; для русских запросов добавляются английские технические термины. `index_code` обновляет векторы после значимых правок. `find_code` оставлен для точных имён и литералов, `list_files` — для поиска пути. Ответы ограничены по объёму, `bin/obj/dist` исключены. Если службы недоступны, используйте узкий `rg`. RagCode в текущей установке не индексирует C#/XAML/PowerShell; Python/Markdown можно искать через него отдельно.

Проверка выбора уровня мозаики, связных пятен, рамок и подсчёта уникальных КЭ (после Debug-сборки):

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\tests\ZonePatches.Regression.ps1
```

Прежний сценарий проверки размещения зон сохранён как архив в `tests/legacy/PreviewZones.Regression.ps1`; его проверки не являются критериями текущего режима пятен.

Для обновления поставки: собрать `Release` x64, скопировать Core и DLL каждого Revit в `dist/stage/addin/{2022,2023,2025,2026}`, выполнить `tools/publish-preview.ps1 -Configuration Release` (он архивирует прежний единый PreviewHost в `dist/backup`), затем собрать `installer/LiraSlabZones.iss` через Inno Setup. Наличие успешной сборки и тестов не означает, что все зоны конкретной модели допустимы к размещению: проверить статистику превышений и предупреждения перед установкой.
