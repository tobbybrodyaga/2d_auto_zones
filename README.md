# LiraSlabZones (2d_auto_zones)

Автозоны дополнительного армирования плит: **ЛИРА-САПР 2024 → превью → Revit 2023**.

Зона создаётся там, где подобранный **As1…As4** превышает фон (см²/м). В Revit размещаются семейства **SUM-30…34** (`SUM-30-Зона дополнительного армирования_R22`).

Ориентиры UX: [SmartRebar](https://promcore.io/blog/smartrebar/), [Smart КР](https://rutube.ru/video/f4198009b09324c7316e697a16613820/).

Подробный алгоритм: [`Шаблон/ALGORITHM.md`](Шаблон/ALGORITHM.md)  
Рабочие заметки / история правок: [`Шаблон/README.md`](Шаблон/README.md)

---

## Требования

- Windows x64
- .NET Framework 4.8 / SDK с поддержкой `net48`
- ЛИРА-САПР 2024 (COM: LiraSapr, LiraResAPI, Sapfir) — для анализа схемы
- Autodesk Revit 2023 — для add-in и размещения зон

Сборка **только x64**: `-p:Platform=x64`.

**UI править только в** `Шаблон/src/LiraSlabZones.Revit2023/UI/`.  
PreviewHost линкует эти файлы — вторую копию XAML не создавать.

Для плиты, повёрнутой в ЛИРЕ, нажмите **«Выровнять по осям»** в группе сопоставления контура.
Программа повернёт геометрию и пересоберёт мозаику, пятна и зоны в строительных X/Y.
При надёжной связи используются оси Revit, без неё — направление контура плиты.
После связи с Revit выравнивание включается автоматически (отключается флажком рядом с кнопкой).
Система координат сохраняется в JSON; поле «Поворот» после выравнивания задаёт оставшийся поворот для Revit.

До деления зон по длине проверяются контур, отверстия и отступ 50 мм (`EdgeOffsetMm`).
Сдвиг использует только запас габарита, сохраняя расчётное пятно и анкеровку. В узком месте
допускается центрирование с равными положительными зазорами — такое исключение показано отдельно.
Если совместить требования невозможно, зона остаётся в предпросмотре с красной диагностикой
«Нарушен отступ от грани»; размещение в Revit останавливается до исправления.
Эта проверка работает независимо от переключателя подрезки/загибов и наличия осей Revit.
После увязки проверяется сохранение покрытия КЭ; при его потере возвращаются исходные кандидаты ряда.

При пересчёте `ZoneOuterEdgeLayout` различает параллельную грань и торец стержня.
Параллельные стержни сдвигаются внутрь на 50 мм; торец у грани получает Г-образный загиб,
два торца — П-образную форму с тем же отступом. Проверяются доступная высота, оправка и
полная длина заготовки до 11700 мм. Геометрическая проверка формы не заменяет расчёт
анкеровки гнутого стержня. На прямом конце сохраняется табличная длина анкеровки.

Расчётная область размещения ограничивается внутренним контуром с отступом `EdgeOffsetMm`:
защитная полоса бетона не требует размещения оси стержня до самой грани. Геометрия КЭ,
исходные As и цветные пятна не меняются. В новых зонах область явно сохраняется как
`DesignEdgeCoverMm`; старые JSON без этого поля сохраняют прежнюю проверку покрытия.

`ZoneBoundaryLayoutSolver` подбирает положение, разрешённые Ø/шаг и разбиение рамок.
`ZoneConflictGroupLayout` перестраивает конфликтующую группу целиком, при необходимости
включая соседей, и принимает замену только после проверки покрытия КЭ, габаритов, шага,
прямой анкеровки, допустимых продольных стыков и привязки к Revit. Поиск автоматически
повторяется, пока уменьшается число конфликтующих пар. Оставшиеся ошибки видимы и
блокируют размещение. Сохранённые ручные зоны перестраиваются только при пересчёте.

Проверка As1 от 28.10.2026, К2, Z=33,650 м (12819 КЭ): 99 → 73 зоны (65 прямых, 8 Г-образных),
23 → 0 конфликтующих пар, 12 → 0 нарушений границы, 2 → 0 непокрытых КЭ.
Исходные КЭ и As сохранены без изменений. Размещение загибов в живом Revit не проверялось;
если семейство не имеет доступного параметра высоты загиба, экземпляр не размещается.

Обновление 29.10.2026: `ZoneLayoutCompactness` разделяет свободные продольные промежутки
с учётом двух анкеровок, уточняет диаметры широких зон по местной потребности As и
объединяет одинаковые соседние ряды с зазором в один шаг. Части продольного стыка
объединяются согласованно. Каждое преобразование сохраняет покрытие, прямую анкеровку,
допустимые стыки, отступ и число конфликтов; итог проверяется повторно по всем КЭ.
Если проверка не проходит, преобразование откатывается.

Для автоматически разделённых рядов сохраняются `SpliceGroupId`, `SplicePartIndex` и
`SplicePartCount`. Стык частей с загибом у края распознаётся после уменьшения габарита:
наличие длины 11700 мм больше не является единственным признаком такого стыка.
Проверки совпадения полосы и минимального нахлёста `2 * LapLenMm` сохранены.

Проверка As4, B30, фон Ø8/200, мозаика и минимальная ширина 300 мм, детализация Max:
167 → 115 зон, 229 → 0 конфликтующих пар, непокрытых КЭ 0, полная диагностика без ошибок.
Расход стали по сумме `L * N * d²` снизился примерно на 23,2%; зон длиной 11700 мм нет.
Повторно проверены As1 и As2: покрытие и геометрическая диагностика без ошибок.
На As3 того же уровня остаются нерешённые случаи: это обновление не является гарантией
нулевых ошибок для всех рядов, настроек и плит. Анкеровка гнутых стержней по СП и
размещение семейств в живом Revit остаются отдельными проверками.

Пересчёт кнопкой и при смене настроек выполняется вне потока интерфейса. На холсте
показаны анимированный индикатор, этап, номер пятна/группы/варианта и прошедшее время.
Готовая замороженная геометрия передаётся на холст одним обновлением; зум и пан сохраняются.
Во время расчёта изменение данных и редактирование зон отключены. Обе боковые панели
меняют ширину перетаскиванием серых разделителей. Подписи зон не перекрывают друг друга;
подпись выбранной зоны имеет приоритет.

В группе «Слои армирования» галочка «Несколько рядов» разрешает одновременный выбор
As1–As4. По умолчанию выбран только As1; без галочки включение другого ряда снимает
остальные. При отключении режима остаётся последний включённый из активных рядов.
JSON с несколькими выбранными рядами автоматически включает этот режим при загрузке.

«Объединить похожие зоны» объединяет соседние полосы с одинаковыми Ø, длиной, шагом и
свойствами семейства при разнице положения вдоль стержней до 50 мм. Длина и общее число
стержней сохраняются; покрытие, прямая анкеровка, границы, отверстия, коллизии и привязка
к осям проверяются. Запланированные продольные стыки этим этапом не разрываются.
Диапазон исходных центров сохраняется в JSON, чтобы повторный запуск не накапливал сдвиг.
Сначала проверяются соседние КЭ через пространственный индекс; затем выполняется общий
контроль с откатом. Этот этап также автоматически запускается после полного пересчёта.
Кнопка работает с готовой раскладкой без повторного построения пятен. Если перед нажатием
изменены расчётные настройки и ожидается пересчёт, выполняется полный пересчёт с ними.

Контроль К2, Z=33,650, 30.10.2026: As2 — 208 → 162 зоны, As4 — 115 → 112;
полная диагностика без ошибок, спецификация стержней и все исходные КЭ/As сохранены.
Само объединение занимает около 1–1,3 с, полный путь кнопки с обновлением окна — 3–3,5 с
на контрольной плите; это не оценка ускорения полного подбора зон.

Локальная сборка (30.10.2026): `версия 1.2/Программа/Объединение_близких_зон`.
Обычный ярлык версии 1.2 указывает на неё; уже открытое старое окно нужно перезапустить.
`Открыть_As4.cmd` открывает проверенный результат без ожидания пересчёта,
а в `output` сохранены отдельные результаты As1, As2 и As4.

Проверки: `tests/ZoneBoundary.Regression.ps1`, `tests/ZoneConflictGroups.Regression.ps1`,
`tests/ZoneBoundary.Ui.Regression.ps1`.
Дополнительные проверки: `tests/ZoneCompactness.Regression.ps1` и
`tests/PreviewRebuild.Regression.ps1 -BuildDirectory <сборка> -SourceJson <JSON>
-Layer As4 -RequireClean` (тест также проверяет работу Dispatcher, индикатор и ширину панели).
Для быстрого пути на готовом JSON добавьте `-MergeOnly` к `PreviewRebuild.Regression.ps1`.
Для сохранённой реальной плиты: `powershell.exe -Sta -File tests/ZoneBoundary.Real.Regression.ps1
-SourceJson <путь к JSON> -OutputJson <путь результата> -RequireCollisionFree` (из каталога `Шаблон`).

## Быстрый старт

### 1. Сборка

```bat
cd /d "путь\к\репо\Шаблон"
dotnet build LiraSlabZones.sln -c Debug -p:Platform=x64
```

### 2. Превью без Revit

```bat
src\LiraSlabZones.PreviewHost\bin\x64\Debug\net48\LiraSlabZones.PreviewHost.exe
```

### 3. Add-in Revit 2023

```bat
powershell -ExecutionPolicy Bypass -File .\install-addin.ps1
```

Перезапуск Revit → вкладка **LiraSlabZones**.

**Перед «Анализ ЛИРА»:** схема открыта в ВИЗОРе, виден нужный фрагмент, арматура плит подобрана.

## Пайплайн

```
LIRA COM (LiraSapr) + LiraResAPI
  → геометрия / оси / отметки
  → только горизонтальные плиты
  → As1…As4
  → зоны As > фон (мозаика → пики → SUM-3)
  → превью
  → размещение в Revit
```

Единицы: координаты ЛИРА — **м**; Ø / шаг / длины зон — **мм**; As / фон — **см²/м**.  
В футы переводит только `ZonePlacer` при вставке в Revit.
